# Release notes

Group by effect, not by area. A user does not care which package a fix landed in.

## Order

Breaking first, always, with the migration step inline. Then new capability, then fixed
behaviour, then everything else in one short line.

## Tone

Past tense for what changed, present for what is now true. Never open with an
announcement — the reader opened a changelog, they are already here.
